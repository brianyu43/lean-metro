# 2026-08-27 린메트로

## 실행 계획

- 1주차 보완: `a * min 1 (b / a) = min a b` 보조정리를 분리하고 기존 스칼라 정리를 재구성한다.
- 2주차 핵심: 대칭 proposal을 곱한 일반적인 off-diagonal detailed balance를 증명한다.
- 예제 연결: `Fin 2` proposal을 명시하고 일반 정리가 기존 전이행렬의 비대각 detailed balance를 설명하게 한다.
- 검증: 각 파일 단독 컴파일, 전체 `lake build`, `sorry`/`admit` 검사 후 커밋한다.

## 1주차에서 보완한 것

- `weight_mul_acceptance_eq_min`: acceptance가 만든 양방향 질량이 `min a b`라는 보조정리
- `mh_balance_scalar`: 두 보조정리와 `min_comm`을 연결하는 짧은 증명으로 재구성

## 2주차에 증명한 것

- `mhAcceptance`
- `mh_balance_symmetric_proposal`
- `two_state_proposal_symmetric`
- `two_state_transition_off_diagonal`
- `two_state_off_diagonal_balance_from_general`

## 수학적으로 핵심이었던 것

- symmetric proposal에서는 `q x y = q y x`이므로 양방향 흐름에 같은 proposal 계수가 곱해진다.
- acceptance ratio에 관한 어려운 경우 분해는 `weight_mul_acceptance_eq_min` 안에서 이미 끝났으므로 다시 증명하지 않는다.
- 2-state 수치 detailed balance는 일반적인 symmetric-proposal 정리의 특수한 경우다.

## 학습 체크포인트

- `weight_mul_acceptance_eq_min`의 두 경우를 기존 파일을 보지 않고 다시 설명한다.
- `mh_balance_scalar`에서 `min_comm`이 필요한 이유를 설명한다.
- `mh_balance_symmetric_proposal`에서 `q`의 nonnegative 가정이 아직 필요하지 않은 이유를 설명한다.
- off-diagonal 식과 rejection이 포함된 diagonal 식의 차이를 설명한다.

## Lean에서 막힌 것

- 실수 나눗셈을 포함한 `mhAcceptance` 정의에는 `noncomputable` 표시가 필요했다.
- `Fin 2`의 대각 두 경우는 `i ≠ j` 가정과 모순이고, 비대각 두 경우만 `norm_num`으로 계산해야 했다.
- 새 프로젝트 모듈을 import하기 전에 `lake build LeanMetro.OffDiagonal`로 `.olean`을 생성해야 했다.

## 다음 정리

- `mhAcceptance`가 0 이상 1 이하임을 증명한다.
- 유한 상태공간에서 대각항을 포함한 `mhTransition`을 정의한다.
